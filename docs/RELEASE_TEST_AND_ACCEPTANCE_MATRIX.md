# SoloForge 测试与发布验收矩阵

> 规则：阻断项任一失败即 No-Go；每项必须保存命令、日志、报告或操作记录。

## 1. 静态与依赖门禁

| 类别 | 操作 | 通过标准 | 证据 | 阻断 |
|---|---|---|---|---:|
| 工作树 | `git status --short` | 发布提交干净 | git 输出 | 是 |
| 依赖 | `npm ci` | 无安装失败，锁文件不变 | 安装日志 | 是 |
| 类型 | `npx tsc --noEmit` | 退出码 0 | 命令日志 | 是 |
| Prisma | `npx prisma validate` | schema 合法 | 命令日志 | 是 |
| 文档 | 链接/版本/状态检查 | 无关键冲突 | 检查记录 | 否/按冲突 |

## 2. 自动化测试门禁

| 类别 | 命令/范围 | 通过标准 | 阻断 |
|---|---|---|---:|
| 单元 | `npm run test:unit` | 全部通过 | 是 |
| Renderer | `npm run test:renderer` | 全部通过 | 是 |
| 集成 | `npm run test:integration` | 全部通过且无隔离掩盖 | 是 |
| E2E | 完整 `tests/e2e` | 核心套件全部通过 | 是 |
| Live | OpenClaw/外部渠道 | 在明确测试环境通过 | 视范围 |
| 覆盖范围 | 审批、审计、配置、部署、外发、备份、认证 | 每个核心场景至少一条闭环测试 | 是 |

`package.json` 的 E2E 白名单和 CI 的全量执行必须统一；遗漏的 `idempotency`、`retry`、`openclaw-bootstrap`、live 外部连接等测试必须明确标记为门禁或非门禁。

## 3. 核心业务验收

| 场景 | 操作 | 预期 | 阻断 |
|---|---|---|---:|
| 工单 | 创建、状态流转、关联审计 | 数据和审计一致 | 是 |
| 权限 | Agent 授权低危/高危工具 | 高危默认拒绝 | 是 |
| 审批 | 未批准执行高危动作 | 拒绝且无副作用 | 是 |
| 出站 | 批准后真实发送 | 成功才 `SENT` | 是 |
| 出站失败 | 超时、错误、重试 | 不伪成功，可重试 | 是 |
| 配置 | diff、审批、apply、回读 | 真实状态一致 | 是 |
| 回滚 | 恢复 lastKnownGood | 审批、结果、审计完整 | 是 |
| 审计 | 查询、导出、验证 hash 链 | append-only、无敏感值 | 是 |
| 备份 | 备份、恢复、错误恢复 | 不破坏原数据 | 是 |

## 4. 安全回归

| 项目 | 验收 | 阻断 |
|---|---|---:|
| 认证 | 缺失/错误 token 返回 401 | 是 |
| E2E 旁路 | packaged app 设置 `SOLOFORGE_E2E=1` 仍拒绝启动或拒绝旁路 | 是 |
| CORS | 任意 Origin 不得获得生产副作用访问 | 是 |
| 审计失败 | 高危动作不在无审计状态下执行 | 是 |
| 敏感字段 | API、审计、日志、备份、导出均无明文 | 是 |
| 错误脱敏 | 响应不泄露路径、token、主机、命令 | 是 |
| Electron | sandbox、contextIsolation、nodeIntegration 配置正确 | 是 |
| 更新 | 未启用自动更新，制品来源可验证 | 是 |

## 5. 数据库和制品验收

- 空数据库迁移成功。
- 上一内部版本升级成功。
- 迁移中断、备份恢复和回滚通过。
- 安装包不含 `dev.db`、测试数据库或明文凭证。
- Windows NSIS、macOS DMG、Linux AppImage 均可安装/启动。
- 每个制品都有版本、commit、平台、架构、SHA-256 和签名状态。

## 6. 手工发布候选验收

指定人员在干净机器完成：

1. 安装。
2. 首次启动和初始化。
3. 创建 Workspace、Agent、工单。
4. 配置本地连接并运行诊断。
5. 创建审批并执行一个安全测试动作。
6. 验证审计和 trace_id。
7. 关闭、重启、升级。
8. 备份、恢复和回滚。
9. 卸载后确认用户数据按策略保留或删除。

## 7. Go/No-Go 记录

发布评审必须记录：

- 版本和 commit
- 测试汇总
- 未解决问题及豁免理由
- 制品 hash/签名
- 数据库迁移结果
- 回滚负责人和步骤
- 技术、安全、发布负责人签字
