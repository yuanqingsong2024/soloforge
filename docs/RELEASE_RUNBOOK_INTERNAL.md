# SoloForge 内部发布操作手册

## 0. 发布前提

本手册只适用于内部候选版和内部稳定版。当前工作树若仍有 P0、集成失败或打包失败，立即停止，不得发布。

## 1. 冻结发布源

- [ ] 确认发布分支和版本号。
- [ ] 审查 `git status --short`，清除临时目录和未跟踪制品。
- [ ] 确认 schema、migration、锁文件和文档已纳入发布提交。
- [ ] 生成变更日志，列出已知限制。
- [ ] 确认没有新功能混入候选版。

## 2. 执行验证

```bash
npm ci
npx prisma generate
npx prisma validate
npx tsc --noEmit
npm run test:unit
npm run test:renderer
npm run test:integration
npm run test:e2e
```

保存所有日志。任一阻断项失败，停止执行并记录 No-Go 原因。

## 3. 数据库验证

- 使用临时空库执行完整迁移。
- 使用上一版本数据执行升级。
- 创建备份并计算 hash。
- 演练恢复和迁移失败处理。
- 确认安装包不包含开发数据库。

## 4. 构建制品

在各平台原生环境运行构建命令：

```bash
npm run build
```

完成后对每个平台：

- [ ] 确认安装包文件名、版本和架构。
- [ ] 生成 SHA-256。
- [ ] 验证签名（如果已配置）。
- [ ] 保存构建日志和 metadata。
- [ ] 确认无测试数据库、凭证和临时文件。

## 5. 安装冒烟

在干净机器：

- [ ] 安装并启动。
- [ ] 验证版本显示。
- [ ] 创建 Workspace、Agent 和工单。
- [ ] 运行连接诊断。
- [ ] 验证未批准高危动作被拒绝。
- [ ] 验证批准、执行和审计结果。
- [ ] 关闭重启后数据仍可读。
- [ ] 从上一版本升级并检查迁移。
- [ ] 验证备份、恢复和回滚。

## 6. 内部归档

归档目录必须包含：

```text
制品/
  安装包
  sha256
  签名信息
  release-metadata.json
证据/
  typecheck.log
  unit.log
  renderer.log
  integration.log
  e2e-report/
  migration.log
  install-smoke.md
  rollback.md
文档/
  changelog
  known-limitations
```

## 7. 发布公告模板

```text
SoloForge {version} 内部发布

发布范围：内部使用 / 受控测试
Git commit：{commit}
支持平台：{platforms}
制品校验：见 SHA-256 文件

已验证：
- {测试与安装结果}

已知限制：
- {限制}

禁止用途：
- 未验证的生产部署
- 未验证的外部发送
- 合规审计依据

问题反馈：{负责人和渠道}
```

## 8. 回滚

发生以下情况立即停止推广：数据损坏、审批绕过、审计缺失、外发假成功、安装无法启动、迁移失败或凭证泄露。

回滚顺序：

1. 停止分发新制品。
2. 保留问题版本、日志和用户数据库备份。
3. 通知内部用户暂停高危操作。
4. 按数据库方案恢复应用或数据。
5. 验证旧版本启动、数据完整和审计连续性。
6. 记录根因、影响范围和修复版本。

## 9. 发布后观察

### 前 24 小时

- 启动失败和迁移失败
- 审批拒绝/批准异常
- 外部发送失败或重复
- 审计写入和 hash 验证
- CPU、内存、数据库锁和崩溃日志

### 第一周

- 真实工作流完成率
- 用户遇到的配置/连接问题
- 备份恢复成功率
- 未实现能力误导反馈
- 是否需要暂停某个高危入口

任何新增 P0 问题都触发 No-Go/回滚，而不是通过文档修改掩盖。
